# 코드 리뷰

## 1. 범위

- 인자 없음: `git diff HEAD`와 추적되지 않은 파일
- PR 번호: `gh pr diff <번호>`
- 경로: 그 파일·폴더 전체

변경이 없으면 그렇게 말하고 끝낸다. 생성물(빌드 결과, lock 파일, 벤더링한 라이브러리, 서브모듈)은 범위에서 뺀다.

## 2. 기준

바뀐 파일의 확장자로 언어를 정하고, 언어마다 아래 순서로 기준을 모은다. 앞에 있는 것이 우선이다.

1. 프로젝트 루트의 `AGENTS.md`·`CLAUDE.md`와 형식 설정(`.editorconfig`, `.clang-format`, `.swiftlint.yml`,
   ESLint·Prettier 설정, `Directory.Build.props`, .NET 분석기 설정 등)
2. 하네스의 언어 규칙 파일

   | 언어 | 확장자 | 규칙 파일 |
   |---|---|---|
   | C/C++ | `.h` `.hpp` `.c` `.cc` `.cpp` `.mm` `.inl`, `CMakeLists.txt` | `~/orca/bckim-harness/rules/cpp.md` |
   | Swift | `.swift` | `~/orca/bckim-harness/rules/swift.md` |
   | C#/.NET | `.cs` `.csproj` `.sln` | `~/orca/bckim-harness/rules/dotnet.md` |
   | JS/TS | `.js` `.jsx` `.ts` `.tsx` `.mjs` | `~/orca/bckim-harness/rules/js.md` |

   규칙 파일에 "리뷰할 때 볼 점" 절이 있으면 그 항목도 확인한다. 파일이 아직 없으면 건너뛴다.
3. 그 언어의 공식 관례

## 3. 읽기

- 바뀐 파일은 diff 조각이 아니라 전체를 읽는다. 선언과 구현이 나뉜 언어는 짝 파일도 읽는다(`.h`/`.cpp` 등).
- 플랫폼·환경별 분기(`#if`, `#if os(...)`, `process.platform`, 조건부 컴파일 기호)가 바뀌었으면 모든 가지를 읽는다.

## 4. 보는 순서

1. **정확성:** 잘못된 동작, 경계 조건, 미정의 동작·널 처리, 데이터 손실
2. **플랫폼·환경 차이:** 한 플랫폼·환경만 고쳤는가, 경로·인코딩·줄바꿈·크기 가정
3. **자원:** 해제 누락, 누수, 수명이 끝난 참조, 불필요한 복사·할당
4. **오류 처리:** 삼킨 오류, 무시한 반환값·Promise, 원인이 빠진 실패
5. **동시성:** 잠금 없는 공유 상태, 경쟁 상태, 메인(UI) 스레드 규칙, 취소·중지 처리
6. **보안:** 외부 입력 검증, 비밀 값 노출, 주입(SQL·명령·경로)
7. **언어 규칙과 스타일:** 2절의 기준

- 바뀐 줄과 그 때문에 깨지는 곳만 지적한다.
- 지적마다 실패 시나리오(어떤 입력·환경에서 무엇이 잘못되는지)를 쓴다. 못 쓰면 버린다.
- 프로젝트에 린터·포매터 설정이 있고 도구가 설치돼 있으면 바뀐 파일에만 돌려 형식을 확인한다.

## 5. 보고

```markdown
## 리뷰: 작업 트리 변경 3개 파일 (C++ 2, TypeScript 1)

1. **[높음] Linux와 Windows의 타임아웃 단위가 다름** — `Source/Network/Socket.cpp:88`
   Windows는 밀리초, Linux는 초로 씁니다. `Connect(Address, 3000, Reason)`이 Linux에서 50분 막힙니다.

2. **[보통] 처리하지 않은 Promise 거부** — `web/src/api.ts:42`
   `fetchUser()` 실패가 잡히지 않아 화면이 로딩 상태에 머뭅니다.

### 스타일
- C++ `!` 대신 `== false`: `Session.cpp:40`, `Session.cpp:57`

### 검증
macOS 빌드·테스트 통과. Windows·Linux는 미검증.
```

- 심각도: 치명(데이터 손실, 크래시, 보안, 빌드 실패) / 높음(잘못된 동작, 환경 간 차이) / 보통 / 스타일.
- 어떤 기준(규칙 파일, 프로젝트 설정, 공식 관례)으로 봤는지 언어별로 한 줄 적는다.
- 빌드나 테스트를 돌렸으면 결과를, 안 돌린 환경은 "미검증"이라고 쓴다.
- 지적이 없으면 "지적 없음"과 확인한 범위를 쓴다.
- 고치는 것은 사용자가 요청할 때만 한다. 고쳤으면 지적마다 `.history/년_월_일_이름.md` 기록을 남긴다(기본 지침 AGENTS.md).
